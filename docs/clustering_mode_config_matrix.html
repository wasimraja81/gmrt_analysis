Standalone Clustering Mode: Config Usage Matrix

Scope: pipeline_cli.py clustering (delegates to run_clustering.py only). This page audits every top-level variable in preprocess_ugmrt.cfg and marks whether it is used by standalone clustering mode.

Back to main docs: api_reference.html → Configuration

Legend (how usage is classified)
YES = read in normal standalone clustering flow (no --refit required) CONDITIONAL = read only when an optional branch is enabled (mainly --refit) INDIRECT = not read directly by run_clustering.py, but influences a derived value/path NO = not used by standalone clustering mode

Your elevation example: SOLVE_ELEVATION_MIN_DEG = YES because it is used in the core load/detection path; SOLVE_ELEVATION_MAX_DEG = CONDITIONAL because it is only used in the optional --refit solve branch.

Classification note

The YES vs CONDITIONAL split is based on whether a parameter is read in the default standalone clustering path itself, or only in optional branches. Optional branches are primarily --refit (post-clustering re-solve) and certain non-default mode toggles. This is why elevation min is YES, while elevation max is CONDITIONAL.
