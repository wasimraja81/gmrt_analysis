uGMRT Analysis Pipeline

Command-first uGMRT bandpass workflow with pipeline_cli.py as the primary interface. Python APIs remain fully documented below for advanced users, debugging, and notebook integration.

Python 3.9+ Phase: Data Diagnostics & Preprocessing Imaging: planned
pipeline_cli.py (Primary User Interface)
Use this command first for all routine operations. Legacy shell scripts are compatibility wrappers over the same interface.
python pipeline_cli.py <command> [args] primary entrypoint

Recommended command set: bandpass, derive, audit, full.

Direct phase drivers: preprocess and clustering are still available for fine control.

Default behavior (pipeline_cli).
• bandpass requires explicit --phase.
• If neither --dry-run nor --no-dry-run is given, default is --dry-run.
• derive/full apply derive presets by default: --step all, --n-iters 15, OUTLIER_METRIC='V', COMPARE_METRICS_FOR_CONVERGENCE=['V','Model'].
• audit defaults to plot-only behavior unless --no-dry-run is passed.
Threshold families (important).
• CLUSTERING_THRESHOLD_JY is clustering-only (Phase-2 audit, including optional final-clustering pass).
• Phase-1 RR/LL/V flagging thresholds are controlled by OUTLIER_METRIC, ANTENNA_FLAG_THRESHOLD_JY, and BASELINE_FLAG_THRESHOLD_JY.
• Clustering supports multi-corr mode: set CLUSTERING_CORR to a list (e.g. ['V','RR','LL']) and set CLUSTERING_THRESHOLD_JY as a per-corr dict (e.g. {'V':5.0,'RR':500.0,'LL':500.0}).
# End-to-end derive + audit (recommended) $ python pipeline_cli.py bandpass \ --phase=derive-and-audit \ --no-dry-run \ --auto --n-iters 100 \ --refit \ --set "SOURCE='3C48'" \ --set "CLUSTERING_THRESHOLD_JY=3.5" # Phase-1 only $ python pipeline_cli.py derive \ --no-dry-run \ --auto \ --n-iters 100 # Phase-2 only (most useful threshold tuning pattern: multi-corr) $ python pipeline_cli.py audit \ --set "SOURCE='3C48'" \ --set "CLUSTERING_CORR=['V','RR','LL']" \ --set "CLUSTERING_THRESHOLD_JY={'V':5.0,'RR':500.0,'LL':500.0}" \ --set "CLUSTERING_THRESHOLD_LOW_JY={'RR':20.0,'LL':20.0}" # Driver-level access (advanced) $ python pipeline_cli.py preprocess \ --step 3 \ --iter-tag iter01 \ --docal on \ --doflag on

Bandpass Derivation Strategy
The goal is a bandpass solution that reflects the true frequency-dependent response of each antenna, not a response smeared by bad data. Any visibility corrupted by RFI or a hardware glitch included in the solver biases the antenna gain toward that outlier — polluting the solution for every baseline of that antenna across all channels. The two-phase workflow below identifies and excludes bad data before the final bandpass is accepted.

Phase 1 — V-based residual outlier loop

Uses Stokes-V = (RR−LL)/2 as a model-free proxy for bad data. A well-behaved calibrator should have V ≈ 0; any excess is a hallmark of RFI or antenna malfunction. The loop iterates: solve bandpass → score antennas/baselines by their Stokes-V residual RMS → flag those above threshold → re-solve with the new flags → repeat until convergence (flag set unchanged, or ε-criteria met). At convergence the bandpass solution and cumulative flag table are written to disk.

Model use in Phase-1 convergence (exactly where 3C48 enters). Auto Phase-1 evaluates two epsilon criteria: C3 uses model-free Stokes-V RMS, while C4 uses RR/LL residual RMS against the Perley-Butler flux model for the selected source. With SOURCE='3C48' and COMPARE_METRICS_FOR_CONVERGENCE=['V','Model'], convergence can be triggered by this 3C48 model-based C4 check.
Phase-1 defaults when invoked as python pipeline_cli.py derive.
• Runs in --dry-run mode unless --no-dry-run is set.
• Uses derive preset --n-iters 15 unless overridden.
• Default scoring preset is OUTLIER_METRIC='V' (model-free for flag ranking).
• Default convergence preset tracks both V and Model (C3 + C4).
# Typical Phase 1 invocation (3C48): $ python pipeline_cli.py derive \ --no-dry-run \ --auto \ --n-iters 100 \ --set "SOURCE='3C48'" \ --set "FLAG_WHAT_TO_FLAG='baselines'" \ --set "CONVERGENCE_EPSILON=0.005" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Phase-1 with explicit RR/LL/V thresholds (per metric): $ python pipeline_cli.py derive \ --no-dry-run \ --auto \ --n-iters 100 \ --set "SOURCE='3C48'" \ --set "OUTLIER_METRIC=('RR','LL','V')" \ --set "ANTENNA_FLAG_THRESHOLD_JY={'RR':180.0,'LL':180.0,'V':30.0}" \ --set "BASELINE_FLAG_THRESHOLD_JY={'RR':800.0,'LL':800.0,'V':150.0}" \ --set "OUTLIER_METRIC_MERGE_STRATEGY='union'" # Same for 3C286 (only SOURCE changes): $ python pipeline_cli.py derive \ --no-dry-run \ --auto \ --n-iters 100 \ --set "SOURCE='3C286'" \ --set "FLAG_WHAT_TO_FLAG='baselines'" \ --set "CONVERGENCE_EPSILON=0.005" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0"
Why 'baselines' mode? Flagging individual baselines is the gentler strategy: a bad antenna accumulates flags on all its baselines over successive iterations and is effectively quarantined without an irreversible whole-antenna flag. Whole-antenna flags are reserved for clearly broken hardware (e.g. mute antenna).

Phase 2 — Clustering detection (threshold exploration & commit)

After Phase-1 converges, the saved bandpass solution and flag table are loaded and the corrected visibilities are passed through a per-channel time-clustering algorithm (run_clustering_detection). This catches short-duration RFI bursts that the per-iteration residual loop misses because they are spectrally confined to a subset of channels. The script produces six interactive plots mirroring notebook cell 15F: corrected amp vs UV-dist, vector-avg spectrum, and Stokes-V vs UV-dist — all shown BEFORE and AFTER the clustering flags. Re-run with different thresholds as many times as needed; only --no-dry-run writes anything to disk.

# Explore thresholds — interactive plots, nothing written: $ python pipeline_cli.py audit \ --set "SOURCE='3C48'" \ --set "CLUSTERING_CORR=['V','RR','LL']" \ --set "CLUSTERING_THRESHOLD_JY={'V':5.0,'RR':500.0,'LL':500.0}" \ --set "CLUSTERING_THRESHOLD_LOW_JY={'RR':20.0,'LL':20.0}" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Tighten one corr only and re-run (fast, no re-solve): $ python pipeline_cli.py audit \ --set "SOURCE='3C48'" \ --set "CLUSTERING_CORR=['V','RR','LL']" \ --set "CLUSTERING_THRESHOLD_JY={'V':3.5,'RR':500.0,'LL':500.0}" \ --set "CLUSTERING_THRESHOLD_LOW_JY={'RR':20.0,'LL':20.0}" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Happy with threshold → commit flags & also re-fit the bandpass: $ python pipeline_cli.py audit \ --no-dry-run \ --refit \ --save-plots \ --set "SOURCE='3C48'" \ --set "CLUSTERING_CORR=['V','RR','LL']" \ --set "CLUSTERING_THRESHOLD_JY={'V':3.5,'RR':500.0,'LL':500.0}" \ --set "CLUSTERING_THRESHOLD_LOW_JY={'RR':20.0,'LL':20.0}" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0"
Tip. Phase 2 re-runs are cheap — the expensive Phase-1 convergence loop does not repeat. Only load_vis_for_source + apply_bandpass_solution + run_clustering_detection are called each time, taking seconds.
Phase-2 defaults when invoked as python pipeline_cli.py audit.
• Defaults to --dry-run: no flag-table writes.
• --refit is off by default (AFTER plots reuse saved Phase-1 bandpass unless enabled).
• --save-plots is off by default (interactive plots only unless enabled).

Recursively discover all .FITS / .fits files under a directory. Returns a list of Path objects.

get_key_header_properties(path) function

Read primary HDU header. Returns a dict with: ngroups, n_ptype, n_chan, n_stokes, obs_date, telescope, instrume, object, freq_hz, chan_width_hz, ra_deg, dec_deg, plus all raw PTYPEs.

ParameterReq/OptTypeDefaultDescription
pathrequiredstr | Path—Full path to the FITS file.
 
props = q.get_key_header_properties('/data/40_014_25jul2021_gsb.FITS')
print(props['n_chan'], props['freq_hz'])
# 256  1267000000.0  (1.267 GHz, L-band)

Read the AIPS AN extension. Returns a list of dicts, one per antenna, with keys: antenna_no, name, x_m, y_m, z_m (ECEF offset from array barycentre), mount, diameter_m.

Read spectral window info from AIPS FQ extension. Returns dict with: ref_freq_hz, n_chan, chan_width_hz, bandwidth_hz, if_band_offset_hz, chan_freq_hz (array of all channel centre frequencies).

Row Index
The row index is a compact in-memory / on-disk summary of every row in the FITS file — which source, which time, which antennas. It makes all subsequent operations fast without re-reading the full file. Always build or load it first.
get_or_build_row_index(fits_path, …) function

Load a cached row index or build one from scratch. On first call for a given FITS file this scans the entire file (minutes for large files); all subsequent calls load the .npz cache in seconds.

ParameterReq/OptTypeDefaultDescription
fits_pathrequiredstr | Path—FITS file to index.
cache_pathoptionalstr | PathNoneExplicit cache file path. Defaults to WORK_DIR/<stem>.index.npz.
cache_diroptionalstr | PathNoneDirectory to place the auto-derived cache file (overridden by cache_path).
force_rebuildoptionalboolFalseIf True, rebuild the index even if a valid cache exists.
validation_modeoptionalstr'fast''fast' checks file size+mtime; 'fast+sha' adds a partial SHA-256; 'sha256' verifies full file hash; 'none' skips all checks.
write_cacheoptionalboolTrueWrite the index to disk after building.
Returns: a dict with keys path, antennas, source_ranges, id_to_name, timestamps_jd, baselines, and more. Pass this dict to all downstream functions.
index = q.get_or_build_row_index(
    '/data/40_014_25jul2021_gsb.FITS',
    cache_dir = '/data/gmrt_40_014/work',
    validation_mode = 'fast+sha',
)
print(index['id_to_name'])   # {1: 'J0024+2902', ..., 7: '3C48', ...}
Loading & Filtering Visibilities
Load raw complex visibility data from the FITS file for a single source. Row-level filters (time, UV range, elevation) are applied at load time.
load_vis_for_source(index, source, …) function

Read visibility rows for a named source into memory. Returns a dict of numpy arrays. Filtering is applied in this order:

① Antenna filter → ② Time range → ③ UV-distance → ④ Elevation

ParameterReq/OptTypeDefaultDescription
indexrequireddict—Row index returned by get_or_build_row_index.
sourcerequiredstr | int—Source name (e.g. '3C48') or integer source ID from AIPS SU table.
ant_rangeoptional(int, int)NoneInclusive range of antenna numbers to include, e.g. (1, 15).
ant_listoptionallist[str|int]NoneExplicit list of antenna numbers or names. Overrides ant_range.
chan_rangeoptional(int, int)NoneInclusive channel index range, e.g. (64, 191). Channels outside are discarded.
stokesoptionallist[str]None (all)List of correlations to load, e.g. ['RR', 'LL'].
max_rowsoptionalint150 000Maximum baseline-rows to load into memory. Randomly sampled when the source has more rows.
flag_all_corrs_if_any_rawvis_flaggedoptionalboolFalseSymmetrise flags across all correlations: if RR is flagged at a sample, also flag LL (and vice-versa).
selectionoptionalDataSelectionNoneA DataSelection object pooling all filter parameters. Explicit kwargs override fields in selection.
timerangeoptional(str|float, str|float)NoneKeep only rows within this UTC/ISO time range. Accepts JD floats or ISO strings like '2021-07-25 19:00:00'.
uvrange_moptional(float, float)NoneKeep rows where min_m ≤ |uv| ≤ max_m (metres).
uvrange_klambdaoptional(float, float)NoneUV range in kilolambda referenced to the band-centre frequency. Takes precedence over uvrange_m when both are given.
elevation_min_degoptionalfloatNoneDiscard rows where the source elevation is below this threshold. Uses astropy AltAz and ECEF from AIPS AN.
elevation_max_degoptionalfloatNoneDiscard rows where the source elevation exceeds this threshold.
 
# Load RR+LL visibilities for 3C48 with elevation ≥ 25°
vis = q.load_vis_for_source(
    index, '3C48',
    chan_range         = (64, 191),
    stokes             = ['RR', 'LL'],
    elevation_min_deg  = 25.0,
    uvrange_klambda    = (2.0, 50.0),
)
# vis.keys(): freqs_hz, vis_complex, weight, flagged, ant1, ant2, ...

chan_rangeoptional(int, int)NoneChannel index range.
uvrange_moptional(float, float)NoneUV range in metres.
uvrange_klambdaoptional(float, float)NoneUV range in kilolambda.
elevation_min_degoptionalfloatNoneMinimum elevation in degrees.
elevation_max_degoptionalfloatNoneMaximum elevation in degrees.
ant_listoptionallist[str|int]NoneAntenna names or numbers to include.
 
sel = q.DataSelection(
    elevation_min_deg = 25.0,
    uvrange_klambda   = (2.0, 50.0),
    timerange         = ('2021-07-25 19:00:00', '2021-07-26 01:00:00'),

result = q.run_iterative_bandpass_workflow(fits_path, index=index, selection=sel)

Source Query Application

A self-contained data-quality and observation-planning tool. Given any source name and the row index, it assembles every property relevant to data selection — elevation track, hour angle, parallactic angle, UV statistics, physical baselines, sensitivity factors, and ready-to-paste --set strings — into a single nested dict. Use print_source_query for a formatted terminal report and plot_source_query for a four-panel diagnostic figure.

query_source(fits_path_or_index, source, …) function

Comprehensive per-source data-quality and observation-planning query. Returns a nested dict with sections: source, file, frequency, timing, pointing, hour_angle, parallactic_angle, uv_coverage, physical_baselines, sensitivity, and data_selection_advice.

ParameterReq/OptTypeDefaultDescription
fits_path_or_indexrequiredstr | Path | dict—FITS file path or a row index dict from get_or_build_row_index.
sourcerequiredstr | int—Source name (case-insensitive) or integer AIPS source ID.
azel_time_step_soptionalfloat60.0Time resolution in seconds for all time-series tracks (Az/El, HA, PA).
elevation_thresholds_degoptionallist[float][15,20,25,30,35,40,45,50,60]Elevation cuts for which to compute time above threshold statistics.
scan_gap_secondsoptionalfloat5.0Gap used to identify scan breaks.
include_uv_rawoptionalboolTrueAttach raw numpy arrays (u, v, ENU) for plotting. Set to False for JSON export.

Return value — top-level keys:

import ugmrt_query as q

Bandpass Calibration
Derive per-antenna complex bandpass gains using an iterative antenna-based solver. No data is written to the FITS file — the solution is returned as a dict and saved separately.
derive_point_source_bandpass(index, source, …) function

Solve for per-antenna gain Gi(ν) using a point-source model. The solver iterates: for each antenna, update gain = mean(Vij / (Gj × model)) over all baseline partners. Converges when max change < tol or after max_iter iterations. Gains can then be smoothed per-channel with a moving average.

Bandpass Diagnostics
Run after each bandpass solve to visualise residuals, score per-antenna/baseline outliers, and detect bad data candidates.
run_bandpass_diagnostics(index, solution, …) function

Applies the bandpass solution to visibilities, computes per-channel residuals (data/gains − model), plots 4-panel diagnostic, and scores each antenna and baseline. The diagnostic plot contains:

① Spectrum — vector-averaged corrected Re(V) per polarisation
② Residuals — Re(data − model) with optional sinusoid fits (fit₁ + fit₂ overlay)
③ Cleaned — residuals after subtracting both sinusoid components
④ Stokes-V — Re(RR − LL)/2 proxy, model-free diagnostic of cross-hand leakage / bad data

Set solution=None and apply_correction=False for an iter00 raw baseline view.

Sinusoid fitting — model & strategy

Panels ② and ③ apply an automatic ripple-removal step. The model fitted to the residual spectrum is: 

f(ν) = a  +  A · sin( 2π ν / P  +  φ )
ParameterInitial guessBoundsMeaning
amedian(y)unconstrainedDC offset of the residual
Astd(y)unconstrained (signed)Amplitude — can be negative
PFFT peak period(P_min, P_max) MHzPeriod in MHz; seeded by FFT periodogram within the allowed range
φ0.0(−π, +π)Fully free phase — not anchored to any channel or to a physical path length

The fit is purely empirical: scipy.optimize.curve_fit minimises the squared residual by adjusting all four parameters simultaneously. The phase φ is initialised to zero but converges freely — it is not referenced to the lowest-frequency channel and carries no physical constraint (e.g. it does not encode a reflection path length).

Two-pass strategy (pass 1 → pass 2):

  • Pass 1 searches the full range period_range_mhz=(0.5, 20.0). The FFT periodogram seeds P to the dominant (largest-amplitude) ripple in that range — typically the long-period (≥ 4 MHz) standing wave caused by dish-feed reflections.
  • Pass 2 runs only if the pass-1 period P₁ > 4 MHz. It fits the pass-1 residuals with period_range_mhz=(0.5, 4.0) to capture the shorter ~1.6 MHz cable-length ripple that the first pass missed.

The diagnostic plot overlays fit₁ as a dotted line and fit₂ as a dash-dot line on panel ②. Panel ③ (Cleaned) shows the doubly-subtracted result.

Limitation: The subtraction is diagnostic only — it is not fed back into the gain solutions. Residual ripple that survives into the calibrated data is controlled by SMOOTH_WINDOW: a 5-channel boxcar has a sinc response H(1/13) ≈ 0.79 at the 1.6 MHz ripple frequency (13-channel period at 0.125 MHz/chan), so gains absorb only ≈79% of the ripple. Set SMOOTH_WINDOW=1 (no smoothing) or SMOOTH_WINDOW=3 (~95% capture) to reduce leakage into corrected residuals.

Iterative Workflow Orchestration
The top-level function that runs the full loop: solve → diagnose → propose flags → update → repeat. This is what the shell scripts call.
run_iterative_bandpass_workflow(fits_path, …) function

Drives the full iterative loop. At each iteration:

① Solve bandpass → ② Save solution → ③ Run diagnostics → ④ Propose flags → ⑤ Accept/reject (auto or interactive) → ⑥ Update flag table → ⑦ Next iteration

Stops early if: flag set is unchanged from previous iteration (C1), or Stokes-V / model-residual RMS stops improving by > epsilon (C3/C4).

Convergence mapping: C3 = model-free V RMS; C4 = RR/LL residual RMS relative to the source flux model (e.g., 3C48 model when source='3C48'). C4 is active only when 'Model' is included in compare_metrics_for_convergence.

# Single iteration, dry-run (preview only) $ python pipeline_cli.py preprocess \ --step all \ --iter-tag iter01 # 10-iteration automated batch, commit to disk $ python pipeline_cli.py preprocess \ --step all \ --auto \ --n-iters 10 \ --no-dry-run # Override config values on the fly $ python pipeline_cli.py preprocess \ --set "SOURCE='3C147'" \ --set "CHAN_RANGE=(50, 200)" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Restrict UV range $ python pipeline_cli.py preprocess \ --set "SOLVE_UVRANGE_KLAMBDA=(2.0, 50.0)"
FlagDescription
--step <1|2|3|4|all>Run individual steps: 1=index, 2=bandpass, 3=diagnostics, 4=flag-proposal, all=full loop.
--iter-tag <tag>Label for this run, e.g. iter01. Appended to all output file names.
--n-iters <N>Number of iterations for --step all.
--autoNon-interactive: auto-accept all flag proposals each iteration.
--dry-run / --no-dry-runControl whether bandpass solutions and flag tables are written to disk.
--config <FILE>Use a different config file.
--set KEY=exprOverride any config variable using Python expression syntax.
v-based-outlier-detection.sh script — Phase 1

Preset compatibility wrapper for Stokes-V based outlier flagging. Equivalent to a pre-configured pipeline_cli.py preprocess invocation.

# Default: dry-run, 15 iterations, interactive (popup plots) $ python pipeline_cli.py derive # Automated non-interactive run, flag baselines only $ python pipeline_cli.py derive \ --auto \ --n-iters 100 \ --set "FLAG_WHAT_TO_FLAG='baselines'" \ --set "CONVERGENCE_EPSILON=0.01" # Apply elevation and UV-range data selection $ python pipeline_cli.py derive \ --auto \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" \ --set "SOLVE_UVRANGE_KLAMBDA=(2.0, 50.0)" # Loosen thresholds and flag antennas only $ python pipeline_cli.py derive \ --set "FLAG_WHAT_TO_FLAG='antennas'" \ --set "ANTENNA_FLAG_THRESHOLD_JY={'V': 8.0}"
DRY-RUN by default. Pass --no-dry-run to commit bandpass solutions and flags to disk (required for Phase 2).
run_clustering.sh  /  run_clustering.py script — Phase 2

Compatibility wrapper for phase-2 clustering detection. Loads the bandpass solution and cumulative flag table written by Phase-1, runs run_clustering_detection with all CLUSTERING_* parameters from the config, then shows six interactive BEFORE/AFTER plots replicating notebook cell 15F:

#BEFORE (no clustering flags)AFTER (clustering flags masked)
1Corrected amp vs UV-dist (RR + LL)Same, clustering rows removed
2Vector-avg spectrum vs PB2017 modelSpectrum with clustering rows removed
3Stokes-V amp vs UV-dist + threshold lineStokes-V with clustering rows removed

Default mode: dry-run — plots only, nothing written. Re-run as many times as needed to tune CLUSTERING_THRESHOLD_JY; each run is fast (no bandpass re-solve). Use --no-dry-run to commit flags; --refit to also re-solve the bandpass with clustering flags active.

# Default: dry-run, interactive popup plots $ python pipeline_cli.py clustering \ --set "SOURCE='3C48'" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Tune thresholds — repeat freely (no disk writes, multi-corr): $ python pipeline_cli.py clustering \ --set "SOURCE='3C48'" \ --set "CLUSTERING_CORR=['V','RR','LL']" \ --set "CLUSTERING_THRESHOLD_JY={'V':5.0,'RR':500.0,'LL':500.0}" \ --set "CLUSTERING_THRESHOLD_LOW_JY={'RR':20.0,'LL':20.0}" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Commit clustering flags to FLAG_TABLE_SESSION: $ python pipeline_cli.py clustering \ --no-dry-run \ --set "SOURCE='3C48'" \ --set "CLUSTERING_CORR=['V','RR','LL']" \ --set "CLUSTERING_THRESHOLD_JY={'V':5.0,'RR':500.0,'LL':500.0}" \ --set "CLUSTERING_THRESHOLD_LOW_JY={'RR':20.0,'LL':20.0}" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Commit + re-fit bandpass + save all 6 plots as PNG: $ python pipeline_cli.py clustering \ --no-dry-run \ --refit \ --save-plots \ --set "SOURCE='3C48'" \ --set "CLUSTERING_THRESHOLD_JY=3.5" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0"
FlagDescription
--dry-run / --no-dry-runDefault: dry-run (plots only). --no-dry-run appends clustering flags to FLAG_TABLE_SESSION.
--refitRe-solve the bandpass with clustering flags active and use that solution for the AFTER plots. Without this flag both BEFORE and AFTER use the same saved BANDPASS_OUT (faster for threshold tuning).
--save-plotsSave the six plots as PNG files to WORK_DIR.
--config FILEUse a different config file (default: preprocess_ugmrt.cfg).
--set KEY=exprOverride any config key. Identical syntax to pipeline_cli.py preprocess --set. All CLUSTERING_* and SOLVE_* keys are accepted.
--log-level LEVELDEBUG | INFO | WARNING | ERROR (default from config).
run_bandpass.sh  —  Wrapper over pipeline_cli.py bandpass script — Phase 1 + 2

Legacy command wrapper. Forwards to python pipeline_cli.py bandpass .... Prefer direct pipeline_cli.py usage in new docs, automation, and user onboarding.

--phaseWhat it doesRequires
deriveV-based iterative loop → converged bandpass + flag table on diskfresh start
auditClustering detection: six BEFORE/AFTER plots, optional commitPhase 1 done
derive-and-auditBoth phases sequentially in one commandfresh start + --no-dry-run

Flags are automatically bucketed: derive-only flags (--auto, --n-iters, --start-iter) are passed only to Phase 1; audit-only flags (--refit, --save-plots) are passed only to Phase 2; everything else is shared.

# First-time full pipeline — derive + audit, commit everything: $ python pipeline_cli.py bandpass \ --phase=derive-and-audit \ --no-dry-run \ --auto \ --n-iters 100 \ --refit \ --set "SOURCE='3C48'" \ --set "FLAG_WHAT_TO_FLAG='baselines'" \ --set "CLUSTERING_THRESHOLD_JY=3.5" \ --set "CONVERGENCE_EPSILON=0.005" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Re-audit with a different threshold (Phase 1 not re-run): $ python pipeline_cli.py bandpass \ --phase=audit \ --set "SOURCE='3C48'" \ --set "CLUSTERING_THRESHOLD_JY=2.5" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Commit clustering flags + re-fit bandpass: $ python pipeline_cli.py bandpass \ --phase=audit \ --no-dry-run \ --refit \ --save-plots \ --set "SOURCE='3C48'" \ --set "CLUSTERING_THRESHOLD_JY=2.5" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0" # Derive only (decide threshold later): $ python pipeline_cli.py bandpass \ --phase=derive \ --no-dry-run \ --auto \ --n-iters 100 \ --set "SOURCE='3C48'" \ --set "FLAG_WHAT_TO_FLAG='baselines'" \ --set "CONVERGENCE_EPSILON=0.005" \ --set "SOLVE_ELEVATION_MIN_DEG=25.0"
FlagPhaseDescription
--phasebothRequired. derive | audit | derive-and-audit
--dry-run / --no-dry-runbothDefault: dry-run. --no-dry-run writes bandpass + flags to disk (both phases).
--autoderiveNon-interactive: auto-accept all flag proposals each iteration.
--n-iters NderiveIteration cap (default 15).
--start-iter NderiveStart labelling output files from iterN.
--refitauditRe-solve bandpass with clustering flags active for the AFTER plots.
--save-plotsauditSave the six BEFORE/AFTER plots to WORK_DIR.
--config FILEbothAlternate config file.
--set KEY=exprbothOverride any config key. Passed to both phases. All CLUSTERING_*, SOLVE_*, and convergence keys accepted.
--log-level LEVELbothDEBUG | INFO | WARNING | ERROR
derive-and-audit requires --no-dry-run. Without it, Phase 1 writes nothing to disk, so Phase 2 cannot load the bandpass solution and will fail. The script prints a warning if you forget.
